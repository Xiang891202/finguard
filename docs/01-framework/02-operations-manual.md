3. Phase 執行流程
3.1 單一 Phase 產出流程
text
1. 確認前置檔案
    ↓
2. 確認前一個 Phase 完成
    ↓
3. 貼上 Phase 模板
    ↓
4. AI 產出 Phase 規劃書
    ↓
5. 檢查：
    ├── ✅ 前端畫面（Vue 3）
    ├── ✅ 後端邏輯（API）
    ├── ✅ 單元測試（pytest / vitest）
    ├── ✅ 整合測試（Critical Path）
    └── ✅ 驗收標準
    ↓
6. 確認驗收標準
    ↓
7. 進入下一個 Phase
3.2 Phase 完成定義
□ 前端畫面可操作
□ 後端 API 端點正常
□ 單元測試通過（≥ 80%）
□ Critical Integration Test 通過
□ 驗收標準全部勾選
□ 交付物清單已產出
3.3 前端規劃顆粒度要求
Vue 元件層級：列出所有 .vue 檔案與職責

UI/UX 元件位置：共用元件引用

互動行為：懸停、點擊、動畫

響應式斷點：三裝置佈局

狀態管理：store、composable

4. 版本鎖定規則
4.1 規則
Phase 開始後，不得直接修改 Framework

若必須修改 → 版本號遞增 → 影響分析 → 決定後續動作

影響分析結果必須記錄

4.2 流程
text
Framework v1.4
    ↓
Phase P0 ~ P6 進行中
    ↓
若需修改 Framework
    ↓
Framework v1.4 → v1.5
    ↓
影響分析：
├── 哪些 Phase 受影響？
├── 是否需要重做？
└── 是否需要補測試？
    ↓
決定：繼續 / 回退 / 重做
5. 常見問題
5.1 AI 忘記前置條件
解法：重新貼上框架規劃書與操作手冊。

5.2 Phase 之間依賴不清
解法：查閱 API 與 Phase 對應表。

5.3 測試標準不明
解法：參考第 20 節「預設決策表」。

5.4 完整版與 MVP 差異不清
解法：每個完整版 Phase 必須標示：

依賴 MVP 哪個 Phase

與 MVP 的差異

新增功能
